# 智付小卡 (SmartPay) — 版本與 Branch 索引

本 `main` branch **不存放可執行程式碼**，僅作為產品線、硬體版本與 branch 位置的索引。
實際程式碼請依下表切換到對應的 branch。

> **本 repo (`analogCoinPay`) 服務的是「類比版娃娃機」**，即 SP2、SP3 產品線。
> 服務「數位版娃娃機」的 SPHP 產品線位於另一個 repo（見 §二）。
> 日後若新增數位版的產品線，不應放入本 repo。

> 最後更新：2026-08-22

## 一、專案沿革

**開心小卡**（舊專案）— 只能幫**數位版**娃娃機做帳目紀錄並上傳雲端。

**智付小卡**（本專案）— 以開心小卡為基礎修改硬體接頭，在帳目紀錄之外新增兩項功能：

1. **對接宏碁票證卡機**
2. **強化「投幣器 + 電眼 / 出表」的類比訊號對接**

### 各產品線實際具備的功能

| 功能 | 開心小卡 | SPHP | SP2 / SP3 |
|---|---|---|---|
| 帳目紀錄 + 上傳雲端 | ✅ | ✅ | ✅ |
| 數位版娃娃機 UART 通訊對接 | ✅ | ✅ | ⚠️ 硬體保留，**未驗證** |
| 對接宏碁票證卡機 | ❌ | ✅ | ✅ |
| 投幣器 + 電眼 / 出表 類比訊號對接 | ❌ | ❌ | ✅ |
| **實際投入使用的機台類型** | 數位版 | 數位版 | 類比版 |

> **SPHP 為何沒有類比對接功能**：開心小卡 v1.1 在類比對接的電路設計不夠完善，且該部分零件未上件。這也是 SPHP 只能服務數位版娃娃機、而類比版必須另開 SP2 產品線的原因。

> **智付小卡其實也保留了數位版的 UART 對接能力**：智付小卡 v1.0.a ~ v2.1 都保留了開心小卡的數位版娃娃機 UART 通訊對接電路，設計構想上可同時服務兩種機台。但因為一直沒有這個需求，**該功能從未驗證過**。以目前的庫存銷售速度推估，開心小卡庫存約需 5~6 年才會售罄，在那之前不太可能用到，實際發生機率很低。

### SPHP 產品線的由來與命名

因開心小卡庫存量大（至少 1000 片），故為其製作**轉接線**並 **rework 拆除 pull-hi 電阻**，使既有庫存可直接接上宏碁卡機，成為 SPHP 產品線。該產品線已執行約一年，僅消耗約 100 片庫存。

> **注意**：開心小卡庫存尚餘約 900 片，**SPHP 產品線短期內不會退役**，仍須持續維護。

代號的由來：

| 代號 | 拆解 | 含義 |
|---|---|---|
| **SPHP** | **SP** = SmartPay（智付）+ **HP** = Happy（開心） | 以開心小卡硬體改裝而成的智付小卡 |
| **SP2**、**SP3** | SP + 序號 | 建立 SP2 時將 SPHP 視為第一代（SP1），後續改用序號 |

## 二、產品線與 Branch 對照

三條產品線沿**兩個軸**演進：

| 演進 | 娃娃機類型 | 狀態顯示方式 | 變的是什麼 |
|---|---|---|---|
| SPHP → SP2 | 數位版 → **類比版** | LCD（不變） | 機台類型 |
| SP2 → SP3 | 類比版（不變） | LCD → **RGB LED** | 顯示方式 |

| 產品線 | 別名 | 娃娃機類型 | 狀態顯示方式 | Branch | 適用硬體版號 | 發行狀態 | 遠端 OTA |
|---|---|---|---|---|---|---|---|
| **SPHP** | SP1 | 數位版 | LCD，完整帳目資訊 + 狀態 | [`SPHP_HWv1`](https://github.com/pc0808f/smartpay/tree/SPHP_HWv1) ⧉ | 開心小卡 v1.1 | **正式發行** | ✅ 支援 |
| **SP2** | — | 類比版 | LCD，完整帳目資訊 + 狀態 | `SP2_HWv1` | 智付小卡 v1.0.a / v1.1 / v2.0<br>**+ v2.1（上件 LCD 時）** | **正式發行** | ✅ 支援 |
| **SP2** (QR 測試版) | — | 類比版 | LCD，完整帳目資訊 + 狀態 | `SP2_HWv1_QR_mpy` | 智付小卡 v2.0（外接 QR scanner） | 少量測試，未正式發行 | ❌ **不支援** |
| **SP3** | — | 類比版 | RGB LED (WS2812)，**僅顯示狀態** | `SP3_HWv2.1` | 智付小卡 **v2.1（上件 RGB LED 時）** 起 | 開發中 | 待定 |

> ⚠️ **v2.1 是 co-layout 板，同一塊板依打件選項可以跑兩條不同的 branch。** 詳見 §三「v2.1 co-layout 與韌體對應」。

⧉ 位於另一個 repo `pc0808f/smartpay`（數位版產品線）；其餘皆在本 repo `propsky/analogCoinPay`。

### 補充說明

**SPHP** — 數位版娃娃機的量產主線。使用**開心小卡 v1.1** 硬體，加轉接線與 rework 改裝而成。

**SP2** — 類比版娃娃機的量產主線。

**SP2 QR 測試版** — 以 v2.0 硬體為基礎，外部再接上 QR scanner，功能沒有減少。因程式碼過大，改用 `.mpy` 預編譯方式瘦身。

**SP3** — SP2 的成本優化版本。v2.0 板庫存即將用盡，故製作成本較低的 v2.1 板。v2.1 為 co-layout 設計，**本次打件選擇上件 RGB LED（單顆 WS2812 狀態指示燈 `LED_STATUS`，GPIO27）而非 LCD**——LCD 的佈線仍保留在板上。公司規劃未來以 RGB LED 方案取代 LCD 方案以降低成本。

> **注意**：即使 v2.0 板停產，外部仍有 v1.0.a 機台在運行，`SP2_HWv1` **仍須持續維護並支援 OTA**。

## 三、硬體版號沿革

本專案有**兩套獨立的硬體版號體系**，版號會重複但指的是完全不同的板子：

| 體系 | 使用的產品線 | 版號 |
|---|---|---|
| **開心小卡** | SPHP | v1.1（僅此一版） |
| **智付小卡** | SP2、SP3 | v1.0 / v1.0.a / v1.1 / v2.0 / v2.1 |

> ⚠️ **開心小卡 v1.1** 與 **智付小卡 v1.1** 是兩塊不同的板子。前者是 SPHP 現役使用的硬體，後者已作廢。引用版號時**務必連同體系一起寫**。

### 智付小卡版號沿革（SP2 / SP3）

| 版號 | 狀態 | 說明 |
|---|---|---|
| v1.0 | **已不存在** | 這批板子已全數手改為 v1.0.a 的 pinout，無對應程式碼 |
| v1.0.a | 有效 | 由 v1.0 手改而來 |
| v1.1 | **已被取代** | 原訂為下一版，因改動過多改稱 v2.0，v1.1 不再使用 |
| v2.0 | 有效 | **庫存即將用盡**，由成本較低的 v2.1 接續 |
| v2.1 | 有效 | **co-layout 板**：LCD 與 RGB LED 位置皆有佈線，打件時二選一。詳見下方說明 |

### v2.1 co-layout 與韌體對應

v2.1 電路板同時 co-lay 了 **LCD** 與 **RGB LED (WS2812)** 兩種顯示方案，交付工廠的 BOM 中**這部分為二選一上件**。本次為降低成本，選擇上件 RGB LED。

因此**同一個版號 v2.1，會依上件選項對應到不同的 branch**：

| v2.1 上件選項 | 狀態顯示 | 對應 branch |
|---|---|---|
| 上件 **LCD** | LCD，完整帳目資訊 + 狀態 | `SP2_HWv1`（沿用既有程式） |
| 上件 **RGB LED** | WS2812，僅顯示狀態 | `SP3_HWv2.1` |

> ⚠️ **韌體的選擇取決於「版號 + 上件選項」，不能只看版號判斷。** 未來若生產 v2.1 板並上件 LCD，該機台屬於 SP2 產品線，直接沿用 `SP2_HWv1` 的程式即可。

## 四、Branch 命名規則

```
SP<產品線代號>_HW<該世代第一塊板的版號>
```

**規則說明：**

1. Branch 名記錄的是**該硬體世代第一塊板的版號**，而非目前支援的所有版號。
2. 後續推出的版號，只要與該世代**軟體相容**，一律沿用同一條 branch，不改名、不開新 branch。
3. **只有當硬體不相容時**，才開出新的 branch 並以新世代第一塊板的版號命名。

**範例：**

- `SP2_HWv1` — 該世代第一塊板為 v1.0，故記為 `HWv1`。後續的 v1.0.a、v1.1、v2.0 皆相容，共用此 branch。
- `SP3_HWv2.1` — 該世代第一塊板為 v2.1，故記為 `HWv2.1`。日後若出 v2.2、v2.3 等相容小改版，仍沿用此 branch。

> 注意：`SP2_HWv1` 省略了小數位（v1.0 → `HWv1`），`SP3_HWv2.1` 則完整保留。命名以「該世代第一塊板的實際版號」為準，格式差異屬歷史因素，不影響規則。

> **例外情況**：v2.1 是 co-layout 板，同時出現在 `SP2_HWv1` 與 `SP3_HWv2.1` 的適用版號中。這不違反上述規則——`SP3_HWv2.1` 命名時記錄的是「SP3 世代第一塊板」，而 v2.1 上件 LCD 的那個變體在功能上屬於 SP2 世代。**判斷韌體時請以「版號 + 上件選項」為準，不能只看版號。**
